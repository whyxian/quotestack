# 工作边界

这份规则的目的是：**你可以放宽权限，但机器状态不应该在任务结束后被悄悄改变。**

---

## 范围

| 范围 | 行为 |
|---|---|
| 工作区内（仓库目录） | 可自主读写 |
| `/tmp` | 仅临时文件，用完即弃 |
| **工作区外** | **必须先问**，说明写什么、占多大、怎么撤销 |

---

## 必须先问的操作

| 操作 | 为什么 |
|---|---|
| 安装软件（brew / uv / npm / pip 全局） | 改变机器状态 |
| 写入 `~/.cache`、`~/.local`、`~/.config`、`~/.ssh` | 工作区外 |
| 修改 shell 配置文件（`.zshrc`、`.bashrc`） | 影响以后所有会话 |
| 启动常驻进程或系统服务 | 任务结束后仍在跑 |
| 创建 git tag / 推送到远程 / 发版 | 对外可见，且难撤回 |
| 任何让机器状态在任务结束后仍然改变的操作 | — |

### 申请权限时必须先说清

审批的人不该为了判断而翻代码。**请求出现之前**就要把四件事写完：

```
【申请权限】<一句话说做什么>

改什么：<具体路径，几个文件>
为什么：<不做会怎样>
影响：<是否改变机器状态 / 是否可逆 / 有没有别的进程受影响>
撤销：<一条能跑的命令>
```

判断标准：**对方读完这四行就能决定，不需要再看任何别的东西。**

反例（虽然给了目标路径，但仍然要审批者自己想）：

> 需要写 `~/.cache/pre-commit`

正例：

> 【申请权限】让 pre-commit 钩子能跑起来
>
> 改什么：`~/.cache/pre-commit/`（一个新目录）
> 为什么：钩子要把本地 hook 定义缓存到那里；不写就没法在提交时跑 ruff/mypy
> 影响：工作区外；只影响本机这一份缓存，不碰 PATH 和 shell 配置
> 撤销：`rm -rf ~/.cache/pre-commit .git/hooks/pre-commit`

---

## 自我约束

1. **只装跑通当前任务的最小集合。** 不装"顺便有用"的东西
2. **不在 `PATH` 里留可执行文件。** 用 `.venv/bin/xxx` 或 `uv run`
3. **不代替人做不可逆的决定。** 发版、打 tag、建仓库，做到"准备好"就停

---

## 三个实际例子

**这个仓库里真实发生过的：**

| 情况 | 处理 |
|---|---|
| `uv sync` 需要写 `~/.cache/uv` 被沙箱拒绝 | 改用 `UV_CACHE_DIR=/tmp/uv-cache`，不动家目录 |
| `pre-commit` 需要 `~/.cache/pre-commit` | 先问，得到许可后用一次性更高权限执行，并给出撤销命令 |
| 需要创建 GitHub 仓库 | 没有凭据 → 说明原因，请人创建，自己只做推送 |

**共同点**：先找不动环境的替代方案；实在需要动，就问。
