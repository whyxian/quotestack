# 05 估值

算出「这只基金今天大概涨跌多少」——在净值公布之前。

---

## 最简用法

```python
estimate = await client.estimate("022430")

print(estimate.change_pct)   # -1.66
print(estimate.basis)        # 'index'
print(estimate.explanation)  # 指数型：跟踪「中证A500指数」实时涨跌 -1.76% × 权益仓位 94.4% = -1.66%
```

**`explanation` 是给人看的**——它说清了这次是怎么算的。想调试或想给用户展示，都用它。

---

## 三个字段先看

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `change_pct` | 估算涨跌 | `None` 表示算不出来，**不是 0** |
| `basis` | 用了哪个公式 | `index` / `holdings` / `none` |
| `coverage` | 覆盖了多少仓位 | 0.94 表示解释了 94% 的资产 |

### `None` 和 `0` 是两件事

```python
if estimate.change_pct is None:
    print("算不出来:", estimate.explanation)
else:
    print(f"{estimate.change_pct:+.2f}%")
```

| 情况 | `change_pct` | 含义 |
|---|---|---|
| 输入缺失 / 过期 | `None` | **未知** |
| 货币基金 | `0.0` | **真的没变化**（净值恒为 1.0） |
| 正常估算 | 数字 | 估算值 |

> **不要 `estimate.change_pct or 0`**——那会把"未知"变成"持平"，
> 用户看到的是一条假的零线。

---

## 两种算法

### 指数型：按跟踪标的算

```
估算涨跌 = 跟踪指数涨跌 × 权益仓位
```

```python
estimate = await client.estimate("022430")
# basis='index'，coverage=0.9437
# 指数 -1.76% × 94.4% = -1.66%
```

系数是**股票 + 其他资产**，不是"股票占净比"。因为 ETF 联接基金 90%+ 的资产是目标 ETF，
不在股票那一栏里：

| 基金 | 股票占净比 | 目标 ETF | 实际权益敞口 |
|---|---|---|---|
| `022430` | 2.67% | 91.7% | **94.4%** |
| `510010` | 97.2% | — | **97.2%** |

**按股票占净比 2.67% 算，估值会接近 0——完全错。** 库已经处理了。

### 主动型：前十大 + 剩余按基准补

```
估算涨跌 = Σ(前十大权重 × 个股涨跌) + 剩余仓位 × 权益基准涨跌
剩余仓位 = 股票占净比 − 前十大合计
```

```python
estimate = await client.estimate("166002")
# basis='holdings'
# explanation: 前十大合计 35.6%，贡献 -4.97%；
#              剩余 34.1% 按权益基准 -1.62% 补（-0.55%）；合计 -2.32%
```

关键点：**剩余仓位只按基准里的「权益类」成分补**。债券、存款成分不参与，因为剩余仓位是股票仓位。

```
166002 基准 = 中证800×70% + 上证国债×25% + 存款×5%
权益组件只有中证800 → 归一后 100%
→ 剩余 34.1% 全部按中证800 补
```

## 准确度到底怎么样

不是宣称，是回测出来的。用历史数据逐日重算，和实际净值涨幅对比：

| 基金 | 类型 | 交易日 | 相关系数 | 平均绝对误差 |
|---|---|---|---|---|
| `022430` | ETF 联接 | 78 | **1.000** | **0.02 pp** |
| `166002` | 主动混合 | 99 | **0.958** | **0.41 pp** |
| `110011` | QDII 主动 | 78 | 0.836 | 0.40 pp |

MAE 0.41pp 意味着：净值 2.68 元的基金，估值误差约 **1 分钱**。

**联接基金几乎是恒等映射**——它本来就只持有目标 ETF。

**QDII 相关性最低（0.836）**：港股美股和 A 股交易时段错开，净值日期对不上。
这不是算法问题，是数据本身的时区错位。

自己复现：

```bash
uv run python benchmarks/estimate_accuracy.py --fund 166002 --days 150
```

## 什么时候算不出来

| 原因 | 表现 |
|---|---|
| 没有资产配置数据 | `change_pct=None`，`explanation` 说明 |
| 跟踪指数查不到行情 | `change_pct=None` |
| 没有季度持仓（主动基金） | `change_pct=None` |
| 画像/持仓拉取失败 | `change_pct=None`，`explanation` 带原因 |

**都不会抛异常**——估值是"尽力而为的参考值"，拿不到输入时说"算不出来"比报错更合适。

想自己判断要不要显示：

```python
if estimate.change_pct is not None and estimate.coverage > 0.7:
    show_to_user(estimate.change_pct)
```

## 看它怎么判定了基准

```python
assumption = estimate.benchmark_assumption
print(assumption.equity)        # ('中证800',)
print(assumption.non_equity)    # ('上证国债', '一年期定期存款基准利率')
print(assumption.unclassified)  # ()
```

`unclassified` 非空说明基准里有规则没认出来的成分——**那时这个估值就不可信**，
值得报给维护者。

## 已知局限

| 局限 | 原因 |
|---|---|
| QDII 误差偏大 | 时区错位，净值和指数不在同一天 |
| 依赖季报持仓 | 有 1–3 个月延迟，换仓了看不出来 |
| 主动基金只看前十大 | 第 11–50 名的持仓被当作"按基准走" |
| 费率、申赎、分红未计入 | 估算的是净值涨跌，不是你的实际收益 |
| 联接基金有跟踪误差 | 目标 ETF 自身的误差会传导 |

**它是"盘中大概在涨还是跌"，不是"预测净值"。** 想要精确数字，等晚上净值公布。
